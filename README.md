# Система обработки потоков сообщений с блокировкой и цензурой

Система потоковой обработки сообщений на Python с использованием библиотеки **Faust (faust-streaming)** и **Apache Kafka**. Реализует функции блокировки нежелательных пользователей и автоматической цензуры запрещённых слов.

##  Классы и логика работы

### Модели данных (`app.py`)

#### `Message`
Модель входящего сообщения.

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `message_id` | str | Уникальный ID сообщения |
| `sender_id` | str | ID отправителя |
| `receiver_id` | str | ID получателя |
| `content` | str | Текст сообщения |
| `timestamp` | float | Unix timestamp отправки |

#### `FilteredMessage`
Модель сообщения после фильтрации.

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `message_id` | str | Уникальный ID сообщения |
| `sender_id` | str | ID отправителя |
| `receiver_id` | str | ID получателя |
| `content` | str | Текст после цензуры |
| `timestamp` | float | Unix timestamp |
| `is_blocked` | bool | Заблокировано ли сообщение |
| `blocked_reason` | str | Причина блокировки |
| `censored_words` | List[str] | Список заменённых слов |

#### `BlockedUser`
Событие блокировки пользователя.

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `user_id` | str | Кто блокирует |
| `blocked_user_id` | str | Кого блокируют |
| `timestamp` | float | Время блокировки |

#### `CensoredWord`
Запрещённое слово.

| Атрибут | Тип | Описание |
|---------|-----|----------|
| `word` | str | Запрещённое слово |
| `replacement` | str | Замена (по умолчанию `***`) |
| `is_active` | bool | Активно ли правило |

### Персистентные хранилища (Tables)

#### `blocked_users_table`
- **Тип**: Faust Table (RocksDB)
- **Ключ**: `user_id` (кто блокирует)
- **Значение**: `set` из `blocked_user_id`
- **Назначение**: Хранение списков заблокированных пользователей для каждого пользователя

#### `censored_words_table`
- **Тип**: Faust Table (RocksDB)
- **Ключ**: `word` (запрещённое слово)
- **Значение**: `CensoredWord`
- **Назначение**: Динамически обновляемый список запрещённых слов

### Агенты обработки (Agents)

#### `process_blocked_users`
Обрабатывает события из топика `blocked_users`.

**Логика:**
1. Получает событие блокировки
2. Извлекает `blocked_user_id` из `blocked_users_table[user_id]`
3. Добавляет в set заблокированных пользователей
4. Сохраняет обновлённый set

**Пример входных данных:**
```json
{
  "user_id": "alice",
  "blocked_user_id": "spammer",
  "timestamp": 1725091200.0
}
```

#### `process_censored_words`
Обрабатывает события из топика `censored_words`.

**Логика:**
1. Получает событие о запрещённом слове
2. Если `is_active=true` - добавляет/обновляет в таблице
3. Если `is_active=false` - удаляет из таблицы

**Пример входных данных:**
```json
{
  "word": "spam",
  "replacement": "***",
  "is_active": true
}
```

#### `filter_messages`
Основной агент фильтрации сообщений из топика `messages`.

**Логика:**
1. Получает сообщение из топика `messages`
2. **Проверка блокировки:**
   - Извлекает `blocked_users_table[receiver_id]`
   - Если `sender_id` в списке заблокированных → `is_blocked=true`
3. **Цензура слов** (если не заблокировано):
   - Извлекает все активные запрещённые слова
   - Заменяет вхождения на `replacement` (регистронезависимо)
   - Сохраняет список заменённых слов
4. Отправляет `FilteredMessage` в топик `filtered_messages`

**Пример работы:**
```
Входящее: {"sender_id": "charlie", "content": "Это spam сообщение"}
Запрещённые: ["spam" → "***"]
Результат: {"content": "Это *** сообщение", "censored_words": ["spam"]}
```

## Инструкция по запуску

### Предварительные требования

- Docker и Docker Compose
- Python 3.11+ (для локального тестирования)
- pip

### Шаг 1: Клонирование и подготовка

```bash
# Перейдите в директорию проекта
cd <project-directory>
```

### Шаг 2: Запуск инфраструктуры

```bash
# Создание Docker-сети
docker network create -d bridge --subnet=10.80.80.0/24 --gateway=10.80.80.1  kafka-internal

# Запуск сервисов Kafka
docker compose -f docker-compose-kafka.yml up -d

# Запуск приложения Faust
docker compose -f docker-compose-app.yml up -d --build

# Проверка статуса
docker ps
```

## Инструкция по тестированию


```bash
# 1. Перейдите в контейнер faust-app
docker exec -it faust-app bash

# 2. Запустите скрипт отправки тестовых данных
python3 send_test_data.py
```

Скрипт автоматически:
- Отправит данные о блокировках в `blocked_users`
- Отправит запрещённые слова в `censored_words`
- Отправит тестовые сообщения в `messages`

Дополнять сообщения или менять порядок можно в файле `test_data.json`

### Проверка результатов

# Просмотр логов Faust приложения

```
docker logs -f faust-app
```

Или в Kafka-UI


## Тестовые данные

Файл `test_data.json` содержит:

### Блокировки пользователей

```json
[
  {"user_id": "alice", "blocked_user_id": "spammer", "timestamp": 1725091200.0},
  {"user_id": "bob", "blocked_user_id": "troll", "timestamp": 1725091200.0}
]
```

### Запрещённые слова

```json
[
  {"word": "spam", "replacement": "***", "is_active": true},
  {"word": "badword", "replacement": "[CENSORED]", "is_active": true},
  {"word": "scam", "replacement": "S***", "is_active": true}
]
```

### Тестовые сообщения

| ID | Отправитель | Получатель | Содержимое | Ожидаемый результат |
|----|-------------|------------|------------|---------------------|
| msg-001 | alice | bob | "Привет! Как дела?" |  Пройдёт без изменений |
| msg-002 | spammer | alice | "Купи мой товар! Это не spam!" | ❌ Заблокировано (spammer заблокирован) |
| msg-003 | charlie | alice | "Это spam сообщение с badword словом" | ⚠️ Пройдёт с цензурой: "Это *** сообщение с [CENSORED] словом" |
| msg-004 | troll | bob | "Троллинг контент" | ❌ Заблокировано (troll заблокирован) |
| msg-005 | dave | eve | "Нормальное сообщение без запрещённых слов" |  Пройдёт без изменений |
| msg-006 | frank | grace | "Содержит spam и scam одновременно" | ⚠️ Пройдёт с цензурой: "Содержит *** и S*** одновременно" |


# Примечание

Возможно потребуется несколько раз запустить скрипты `send_test_data.py` и `read_filtered_messages.py`

В первом случае сообщения пройдут через бизнес-логику, процензурируются, но пройдут до получается. После этого сработает логика "блокировки" пользователя и повторная попытка отправить сообщение уже не пройдет.
